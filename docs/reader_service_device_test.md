# 카드 리더 서비스 실기기 시험 절차

대상 기기: 토스프론트 실기기 (2026-11-23 시험은 무선 adb 연결). 시험 전에는 기기에 아무것도 설치하지 않았습니다.

2026-11-23 0단계에서 확인한 기기 상태(문서 처음 가정과 다름):
- 빌드 `LineageOS for Toss Front | 20260928.001 | UNOFFICIAL`.
- Sunmi 결제 서비스 `com.sunmi.pay.hardware_v3`는 설치돼 있지 않습니다(`pm path` 출력 없음, exit 1).
- 설치된 카드 리더 앱은 1.2.0이 아니라 **1.1.0**(versionCode 2)입니다. 기기에서 받은 apk는 `dist/toss-front-card-app-1.2.0-sp.apk`와 바이트까지 같고
  (sha256 `9f6e8ae0…0db7`, 직접 연결 빌드인데 버전 이름이 1.1.0), 서명은 카드 리더 앱 키 `6540effc…a710`로 1.3.0과 같습니다. 이 앱이 `/dev/ttyS3`를 열어 두고 약 50ms마다 `IC_STATUS`(cmd 0A)와 `MSR_READ`(cmd 01)를 계속 보냅니다.
  그래서 우리 서비스가 포트를 열기 전에 카드 리더 앱을 먼저 멈춰야 합니다(`am force-stop com.toss.cardapp`).
각 단계의 **사장님** 항목은 기기 앞에서 해 주셔야 하는 일입니다. 나머지는 Mac에서 adb로 진행합니다.

카드 리더 앱은 **지우지 않고** `adb install -r`로만 업데이트합니다. 기록·회원·규칙은 그대로 남습니다.

## 순서

### 0. 준비
- **사장님**: 토스프론트를 USB로 Mac에 연결하고 화면을 켜 둡니다.
- **사장님**: 카드 리더 앱의 **기록** 화면에서 기록 건수를 확인해 알려 주세요. 업데이트 뒤에 같은지 비교합니다.
- adb: `adb devices`, Android 버전, Sunmi 결제 서비스 설치 여부(`pm path com.sunmi.pay.hardware_v3`), 카드 리더 앱 버전을 기록합니다.
- 루트 권한은 쓰지 않습니다. 포트를 누가 열었는지는 루트 없이 확인합니다(아래 "포트 점유 확인").

### 1. 서비스와 시험 앱 설치 (카드 리더 앱은 아직 기존 버전, 2026-11-23 기기는 1.1.0)
- adb: 서비스, trusted, second, foreign 시험 앱을 설치하고 서비스를 시작합니다.
- 확인: 1.2.0 앱의 자동 실행 대기가 `/dev/ttyS3`를 쓰는 중이면 시험 앱의 카드 대기가 `BUSY`로 거절됩니다.
  서비스는 포트를 건드리지 않습니다. 직접 연결끼리 충돌하지 않는지 보는 단계입니다.

### 2. 카드 리더 앱 1.3.0 업데이트
- 2026-11-23 상태: 기기는 아직 1.1.0입니다. 이 1.1.0은 `dist/toss-front-card-app-1.2.0-sp.apk`와 같은 파일이라, 이 단계는 실제로는
  "1.2.0-sp 직접 연결 빌드(versionCode 2) -> 1.3.0(versionCode 4)" 업데이트입니다. 사장님의 기록 건수와 설치 승인을 기다리는 중입니다.
- 1.3.0 설치는 되돌릴 수 없습니다(아래 "되돌리기"). 기록은 `adb install -r`로만 유지됩니다.
- 미리 백업할 방법이 없습니다: 앱이 `allowBackup="false"`라 `adb backup`이 빈 파일을 만들고, 루트는 쓰지 않습니다.
  루트로 `/data/data`를 묶어 두더라도 기록은 AndroidKeyStore의 AES 키(`Vault`)로 암호화돼 있고, 이 키는 `/data/data` 밖에 있으며 앱을 지우면 함께 지워집니다.
  그래서 그 묶음으로는 기록을 되살릴 수 없습니다. 같은 키로 서명된 `install -r`은 앱 아이디와 키를 그대로 두므로 기록을 읽을 수 있고, 서명이 다르면 설치가 거절될 뿐 기존 앱은 남습니다.
- adb: `adb install -r toss-front-card-app-1.3.0.apk`. 업데이트 뒤 앱의 자동 실행 대기는 서비스를 통해 다시 시작합니다.
- **사장님**: 기록 건수가 0단계와 같은지 확인해 주세요.
- 확인: 포트를 연 프로세스가 서비스 하나뿐인지 봅니다(아래 "포트 점유 확인").

### 3. 카드 대기가 없을 때 폴링 없음
- **사장님**: 카드 리더 앱 **설정**에서 "카드 넣으면 자동 실행"을 끄고 홈으로 나갑니다.
- 확인 1: 연결한 앱이 없으면 30초 동안 리더 명령 로그(`SpLink`)가 0줄이고 포트가 닫혀 있습니다.
- 확인 2: trusted 시험 앱이 연결만 하고 대기하지 않은 상태에서도 30초 동안 리더 명령이 0줄입니다.

### 4. 카드 리더 앱이 서비스로 읽기
- **사장님**: 카드 리더 앱을 열고 IC 카드를 꽂았다가 빼 주세요. 그다음 마그네틱 카드를 한 번 긁어 주세요.
- 확인: 앱 화면에 카드 정보가 나오고, 서비스 로그에 `session … IC read`와 `MSR handed over`가 찍힙니다. 앱 프로세스는 포트를 열지 않습니다.

### 5. 다른 앱(시험 앱)이 서비스로 읽기, BUSY
- **사장님**: 카드 리더 앱 화면을 닫고, "Card Reader Sample"을 열어 **카드 대기**를 누른 뒤 IC 카드를 꽂았다가 빼 주세요.
  한 번 더 **카드 대기**를 누르고 마그네틱 카드를 긁어 주세요. 화면에는 가린 카드번호(끝 4자리)만 나옵니다.
- adb: 카드 리더 앱 화면을 연 상태에서 second 시험 앱으로 카드 대기를 요청합니다. `BUSY`가 나와야 합니다.

### 6. 허용되지 않은 키
- adb: foreign 시험 앱을 실행합니다. 모든 호출이 `NOT_ALLOWED`이고, 서비스 로그에 `refused uid=…`가 찍혀야 합니다.

### 7. 자동 실행 복구
- **사장님**: 설정에서 "카드 넣으면 자동 실행"을 다시 켜고 홈으로 나간 뒤 IC 카드를 꽂아 주세요. 리더 화면이 열려야 합니다.

### 8. 로그 점검
- 시험 중 받은 logcat 전체에서 카드번호처럼 보이는 숫자열(12자리 이상)과 트랙 형식을 검사합니다. 0건이어야 합니다.

### 선택: 부팅 시 시작
- 재부팅이 필요합니다. 사장님이 허락하실 때만 진행합니다. 부팅 뒤 서비스 프로세스가 떠 있는지만 확인합니다.

## 포트 점유 확인 (루트 없음)

- `SpLink` 로그: 포트를 열 때 `open pid=<pid> link ok`, 닫을 때 `close`를 남깁니다. `adb logcat -d -v threadtime -s SpLink:* ReaderService:* ReaderSessions:*`로
  어느 pid가 열고 닫았는지 봅니다(threadtime 형식의 셋째 칸이 pid). 이 기기의 logcat은 `-v pid`를 지원하지 않습니다.
- 기준 시각은 `adb shell 'date +"%m-%d %H:%M:%S.000"'`처럼 기기 쪽 명령 전체를 작은따옴표로 감싸야 합니다. 감싸지 않으면 기기 셸이 공백에서 잘라 날짜만 나옵니다.
- 로그 버퍼는 돌아가며 지워집니다. 버퍼에 `open` 줄이 없다는 것만으로 "포트를 열지 않았다"고 판정하지 않습니다. 해당 pid의 생애 전체가 버퍼 안에 있을 때만 판정하고, 아니면 "판정 불가"로 적습니다.
- `adb shell pidof com.toss.cardreader.service com.toss.cardapp`로 위 pid가 어느 앱인지 맞춰 봅니다.
  카드 리더 앱 1.3.0의 pid로 `open`이 찍히면 실패입니다.
- 서비스가 포트를 쓰지 않은 경우 `ReaderSessions`가 BUSY를 남기고, 시험 앱 화면에 `BUSY`가 나옵니다.

## 되돌리기
- 서비스와 시험 앱 제거: `adb uninstall com.toss.cardreader.service` 및 시험 앱 3개. 카드 리더 앱 1.3.0은 Sunmi 서비스나 직접 연결로 계속 동작하고, 기록은 그대로입니다.
- 카드 리더 앱을 1.2.0으로 되돌리는 다운그레이드는 기록 삭제 없이는 보장되지 않으므로 하지 않습니다.
